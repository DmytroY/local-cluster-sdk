# Local Cluster SDK

A lightweight Python SDK for executing AI workloads against an OpenAI-compatible chat completion endpoint hosted on a local cluster or another compatible backend.

The package is intentionally small and opinionated:

- it sends a standard OpenAI-style payload to `http://{host}:{port}/v1/chat/completions`
- it accepts a workload object with prompt/system prompt/settings
- it returns the first assistant message content from the response
- it raises targeted exceptions for connection issues and slow model swap scenarios

## Features

- Local cluster execution against a model server
- OpenAI-compatible payload generation
- Simple `AIClusterClient` interface
- Clear exception handling for unreachable clusters and model-loading timeouts
- Provider-agnostic design at the HTTP payload level

## Installation

```bash
pip install local-cluster-sdk
```

For development or tests:

```bash
pip install "local-cluster-sdk[test]"
```

## Quick Start

```python
from local_cluster_sdk import AIClusterClient, AgentWorkload

client = AIClusterClient(host="127.0.0.1", port=11434)

workload = AgentWorkload(
    prompt="Write a Flask health check endpoint",
    system_prompt="You are a senior Python engineer.",
)

result = client.execute(workload, resource="coder")
print(result)
```

## How it works

`AIClusterClient` builds a URL like this:

```python
http://{host}:{port}/v1/chat/completions
```

and posts a JSON payload generated by `AgentWorkload.to_openai_payload(model_name=resource)`.

The generated payload looks like this:

```python
{
    "model": "coder",
    "messages": [
        {"role": "system", "content": "You are a senior Python engineer."},
        {"role": "user", "content": "Write a Flask health check endpoint"}
    ],
    "temperature": 0.2,
    "options": {"num_ctx": 4096}
}
```

`execute()` returns `data["choices"][0]["message"]["content"]` from the server response.

## API

### `AIClusterClient`

```python
from local_cluster_sdk import AIClusterClient

client = AIClusterClient(host="127.0.0.1", port=11434)
```

Parameters:

- `host: str` - host of the model server, default `"127.0.0.1"`
- `port: int` - port number, default `11434`

Methods:

- `execute(workload: AgentWorkload, resource: str) -> str`
  - sends the workload to the configured chat completions endpoint
  - returns the generated text from the first choice

### `AgentWorkload`

```python
from local_cluster_sdk import AgentWorkload

workload = AgentWorkload(
    prompt="Summarize this codebase",
    system_prompt="You are a careful reviewer.",
    temperature=0.2,
    num_ctx=4096,
)
```

Fields:

- `prompt: str`
- `system_prompt: Optional[str] = None`
- `temperature: float = 0.2`
- `num_ctx: int = 4096`

The client uses `resource` as the model name, so the model is selected by the backend server or provider, not by a separate SDK-specific abstraction.

## Using other AI providers

The SDK is intentionally backend-agnostic at the protocol level: it only needs an OpenAI-compatible `/v1/chat/completions` endpoint. In practice, this means you can point the SDK at other compatible model services by changing the configured `host` and `port`.

Important note: the current implementation builds URLs as `http://{host}:{port}` and does not include provider-specific auth headers or HTTPS handling. This is fine for local servers and many simple setups, but providers that require HTTPS and API keys may need a small wrapper or a client change.

### Example: Local Ollama

```python
from local_cluster_sdk import AIClusterClient, AgentWorkload

client = AIClusterClient(host="127.0.0.1", port=11434)

workload = AgentWorkload(
    prompt="Explain recursion in simple terms",
    system_prompt="You are a teacher.",
)

result = client.execute(workload, resource="llama3.1")
print(result)
```

### Example: Groq

This is conceptually supported as long as the endpoint is OpenAI-compatible and your environment can reach it.

```python
from local_cluster_sdk import AIClusterClient, AgentWorkload

# This example shows the intended pattern; the current client does not
# add Groq-specific auth or HTTPS handling automatically.
client = AIClusterClient(host="api.groq.com", port=443)

workload = AgentWorkload(
    prompt="Write a production-ready deployment checklist",
    system_prompt="You are a DevOps engineer.",
)

result = client.execute(workload, resource="llama-3.1-8b-instant")
print(result)
```

### Example: OpenRouter

```python
from local_cluster_sdk import AIClusterClient, AgentWorkload

# Same concept: set the endpoint host and model name you want to use.
client = AIClusterClient(host="openrouter.ai", port=443)

workload = AgentWorkload(
    prompt="Compare Python async patterns for a web API",
    system_prompt="You are a backend engineer.",
)

result = client.execute(workload, resource="openai/gpt-4o-mini")
print(result)
```

### Provider switching pattern

```python
from local_cluster_sdk import AIClusterClient, AgentWorkload

providers = {
    "local": {"host": "127.0.0.1", "port": 11434},
    "groq": {"host": "api.groq.com", "port": 443},
    "openrouter": {"host": "openrouter.ai", "port": 443},
}

provider = "local"
config = providers[provider]
client = AIClusterClient(**config)

workload = AgentWorkload(prompt="Explain distributed tracing")
result = client.execute(workload, resource="llama3.1")
print(result)
```

This pattern makes the SDK easy to reuse across different OpenAI-compatible model backends, even though provider-specific configuration still needs to be handled explicitly in the client if the backend requires things like API keys or HTTPS.

## Error handling

The SDK raises these exceptions:

```python
from local_cluster_sdk import (
    AIClusterClient,
    AgentWorkload,
    ClusterUnreachableError,
    ModelSwapTimeoutError,
)

client = AIClusterClient()
workload = AgentWorkload(prompt="Hello")

try:
    result = client.execute(workload, resource="coder")
    print(result)
except ClusterUnreachableError as exc:
    print(f"Cluster unreachable: {exc}")
except ModelSwapTimeoutError as exc:
    print(f"Model swap timeout: {exc}")
```

### Exception hierarchy

- `ClusterSDKError` - base class for SDK exceptions
- `ClusterUnreachableError` - raised when the server is down or cannot be reached
- `ModelSwapTimeoutError` - raised when the backend takes too long to load a model into memory

## How the request is built

The request is a standard POST to the completions endpoint with `json=payload` and a timeout tuple of `(10.0, 45.0)`.

```python
response = requests.post(
    self.endpoint,
    json=payload,
    timeout=self.network_timeouts,
)
```

This means the SDK is designed for roughly the same behavior as a lightweight HTTP wrapper around a local model inference service, rather than a fully-featured provider client with auth and streaming support.
